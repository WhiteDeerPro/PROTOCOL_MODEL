# Protocol Model 0.4.1

0.4.1 在 0.4.0 的 interface、VirtualDut 和 SystemProtocol 边界上继续固化 CHI Issue H 的可执行
lifecycle，并重整公开文档的权威入口。它仍是 pre-1.0 technical preview；下述能力均以具名 profile、
participant 集合和构造证据为边界。

## 本版闭合的路径

- cache 与 Home 通过 canonical VirtualDut binding、address claim、Home authority 和 coherence domain
  membership 进入 resolved CHI construction；
- clean/dirty coherence 增加 CleanUnique、MakeUnique、Evict、ReadUnique Retry/NDERR、
  WriteBackFull、WriteEvictFull/WriteEvictOrEvict 及受限 same-line Snoop 组合；
- `WriteNoSnp{Full,Ptl}` 使用 original TxnID、Home DBID、自然 byte lane 与协议无关 backing
  prepare/commit contract 完成 Immediate Write；
- non-snoop Exclusive Ptl 使用 `SrcID+LPID` monitor、EXOK/OK checkpoint 和竞争写失效形成一条
  aggregate Home lifecycle；
- returning Atomic 支持 Size=0..3 的 `AtomicSwap` 与 `AtomicLoad ADD`，共享 DBID、same-line
  serialization 和 backing version，并返回更新前的值；
- clean ReadShared DCT 使用 forwarding Snoop、peer `CompData`、`SnpRespFwded` 与 `CompAck` 完成
  乱序双输入 join；
- direct 与含 XP 的 topology witness 闭合相应 REQ/RSP/SNP/DAT flow，异构 ring/star 和 4×4 mesh
  Showcase 分别展示拓扑形态与长路径。

## 文档与发布边界

canonical 架构、实现状态、近期 Roadmap、源码导航和 Showcase 各自维护稳定概念、当前能力、施工顺序、
公共入口与可执行证据。公开源码树保留运行与阅读所需的生产文件；本地测试、review 报告和自动化助手配置
属于维护工作区，不成为生产包的反向依赖。

## 当前边界

- CHI capability catalog 和 opcode lifecycle 仍是 Issue H 的受限增量切片，不表示完整 RN/HN/SN 或
  完整 Atomic、DVM、DCT、Retry/error catalog；
- Atomic 当前限定 little-endian、`PAS=0`、Normal Non-cacheable、`SnpAttr=0/SnoopMe=0` 的
  1/2/4/8-byte profile；
- non-snoop Exclusive 当前限定单 aggregate Home monitor profile；coherent Exclusive、overflow 和
  一般 multi-LP 仍待独立切片；
- Immediate Write、Atomic、Exclusive 与 coherence 还没有共同 backing-owning Home runtime；
- dynamic multi-Home/SAM、一般 Owned/dirty forwarding、HN→SN topology-visible commit、
  multi-packet DAT 和外部 RTL conformance 仍按状态页记录为后续能力。
